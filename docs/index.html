grid-bench

Open-source power system tools timed on the same problems, where every result is graded by an oracle that no tool under test takes part in: no speed number without a correctness number. Choose a problem; how it is set up and graded is shown with its results.

Scoreboard

Each cell counts its column's cases: ✓ / ✗ / FAILED. ✓: the oracle accepted the result. ✗: the tool returned a result the oracle rejected. FAILED: the tool raised or did not converge (see Failures). ·: the tool reads none of the column's cases.

Thread scaling

One panel per case, same y-axis. Dashed grey: ideal scaling (speedup equal to the thread count). Filled point: the oracle verified that thread count's solution; hollow: it did not. Hover a point for the time.

How every problem is measured

  • Solve is timed warm: one persistent model, one untimed warm-up solve, then repeated solves (median shown). Import is the median of 3 cold loads after one warm-up load.
  • Oracle. Tier 1 (MATPOWER cases): the residual V·conj(Ybus·V) − S with Ybus built from the .m file by the benchmark itself. Tier 2 (CGMES fixtures): deviation from the case's published SV solution. Each problem's own check builds on these; it is described with the problem, above.
  • Settings. Every setting of every tool is justified in its adapter's docstring, including what it deliberately does not do.
  • Memory is the peak RSS of a fresh process loading and solving the case, minus the peak after importing the tool (values below 1 MB are drawn at 1 MB on the log axis). Only the benchmark process counts: cgmes2pgm's Fuseki server is not included.
